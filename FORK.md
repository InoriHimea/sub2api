## Group exhaustion and upstream failures

- Account selection stops when its candidate pool is exhausted; it never clears failed-account exclusions to call the same unavailable accounts again. Explicitly configured same-account retries still apply before exhaustion, and terminal request errors stop immediately.
- Retryable account failures retain one coherent response, including its body and Retry-After: 429 outranks 503 regardless of account order. Ordinary upstream 503 remains 503 instead of becoming 502. Existing credential-error mappings, passthrough rules and stream-terminal safeguards remain in force.
- Default 429/503 responses include the selected upstream's safe scalar message, bounded to1024 UTF-8 bytes. Secrets, account/organization/project identifiers and network addresses are redacted or replaced by a generic message; structured quota details and credential failures are not exposed.
- Empty schedulable pools enter a fixed five-second negative cache. After upstream failures, shared cooldown requires evidence covering the entire schedulable pool, not merely a capability-filtered subset; profit vetoes, concurrency rejection and fixed-account bindings are not upstream-failure evidence. A healthy account outside an exhausted narrow capability must not be blocked.
- Cooldown keys use the original group/model/platform, before fallback/composite rewriting. The cache is process-local and bounded to4096 entries; requests return503 or the selected429 with Retry-After, without extending the deadline. Expiry resumes account discovery. Raw upstream bodies and account details are not cached. Existing in-flight requests and other replicas are not stopped by this local gate.
- Fixed-account video retrieval preserves task ownership and is not gated by a shared generation-pool cooldown. Model-not-found, compact capability and unrelated storage failures retain their existing classification rather than becoming empty-pool cooldowns.
- Local regression: `go test ./internal/handler ./internal/service -count=1 -timeout=900s`; actual loopback HTTP cases cover503/503/503, all three429 orderings, coherent error/header selection and zero additional upstream calls during503/429 cooldown. Deterministic service cases cover empty-pool discovery, exact expiry, isolation and healthy-account protection. Local verification is not a deployment.

## Upstream synchronization

1. Fetch official refs with `git fetch upstream`. Record the exact candidate commit/release relative to `upstream.lock.json`; never build or deploy an unreviewed floating `main/latest` reference.
2. Merge a reviewed official commit into an isolated synchronization branch derived from downstream `main`. Preserve ancestry; stop on conflicts or regression failures instead of force-pushing or resetting maintained work.
3. Compare each downstream extension with current native upstream behavior. Once upstream has an equivalent implementation proven against the contract, remove the duplicate downstream difference. Temporary bug workarounds remain separate from permanent features.
4. Update the intake lock and `upstream-main` anchor through reviewable commits. Only fetch from `upstream`; do not push downstream commits there. Local `main` tracks `origin/main`.

#### First-job activation barrier: offline qualified, staged; live bootstrap blocked

`deploy/bamboo/agent-isolation/` is separate from the frozen bootstrap and release controller. `ActivationGate` blocks after native registration but before all five native command/event/build/heartbeat consumer definitions. It compares the **post-registration in-memory** id, native UUID and server base URL against a trusted fixed profile; it never reads actual `agent.cfg` or business credentials. A missing record that returns a different id is rejected even if native configuration save fails and the old disk id survives. The genuine native parent-first loader selects the overlays, while `RemoteAgent` remains vendor-defined. Missing overlays cannot silently fall back to stock consumer startup. An upgrade or incompatible installed bootstrap fails closed; check the installed frozen12.1.10 loader against this12.1.12-qualified profile before any integration, do not replace vendor assets/pins implicitly.

## Native HTTP observation contract (OBS-01)

- The current upstream already owns response-model observation, `created_at` filling, `sequence_number` and protocol normalization. The fork adds only HTTP dispatch/body/parser observations; it does not carry alternate implementations of those upstream fixes or change protocol, retry, timeout, account/model selection or TTFT policy.
- `gateway.openai_http_observation_success_sample_rate` (environment `GATEWAY_OPENAI_HTTP_OBSERVATION_SUCCESS_SAMPLE_RATE`) must be finite in `[0,1]`, default0. Sampling is chosen once per request sequence, retained across retries, and emits completion metadata only for the native Responses parser. Configure the actual service environment/YAML; a Compose `.env` entry alone is not container injection.
- `openai.upstream_http_complete` is a structured log, not an Ops success-error row. Completion requires an observed native `response.completed`/`response.done` with no failure or cancellation; EOF or `[DONE]` alone is not proof of completion. Client write failures/cancellation do not acquire provider-failure attribution.
- Failure diagnostics attach immutable per-attempt snapshots to existing Ops error JSON and emit `openai.upstream_http_failure` with bounded stage classification. Credential-acquisition failures do not inherit prior HTTP-attempt data. New fields retain allowlisted protocol/ALPN/network/rejection codes, numeric times/counts and numeric peer address only; no prompts, tokens, headers, arbitrary error text or provider payload are retained by these observations.
- Transport timing starts at dispatch; SSE timing measures parser processing, not packet arrival. Existing `first_token_ms` retains its forward-start clock. Downstream write/flush timings measure actual writer calls, not first-output staging and not proof of client receipt or Internet backpressure. `-1` means unobserved, not zero latency.
- Local synthetic checks cover real HTTP→Forward→TLS H1/H2, unchanged SSE bytes with sampling0/1, authoritative terminal/cancellation/writer failures, non2xx redaction, H2 resets, immutable retry snapshots and native flush/timestamp regressions. No live model requests, production error-table insertion, deployment or OS-level network namespace isolation is claimed.
